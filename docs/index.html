What it does

Cell-based offer ingestion

Accept driver offers per H3 cell, queue them with TTL and priority, then surface queue depth and counters.

Push path

At-least-once delivery

The push gateway keeps live messages until client ACK, then prunes them explicitly after receipt confirmation.

Observability

Metrics and health

Micrometer counters and gauges expose cell queue depth, push queue depth, and active session state.

Quick start

Run locally

mvn spring-boot:run

The service starts on port 8080 for HTTP and 9090 for gRPC.

Sample request

Create an offer

curl -s -X POST http://localhost:8080/cells/8928308280fffff/offers \
  -H 'Content-Type: application/json' \
  -d '{"driverId":"d-001","riderId":"r-001","priority":5,"ttlMillis":5000}'

Architecture

Queue-to-push flow

  1. DispatchController accepts per-cell offers and forwards them into the queue manager.
  2. OfferFlusher drains due offers and hands them to the push client.
  3. PushServiceImpl stores messages, handles ACKs, and drains streams on readiness.
